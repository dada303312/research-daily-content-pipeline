# 从日更公众号到可复用 Codex Skill：我如何把论文搜集、撰稿和发布串成一条流水线

> Skill 仓库：https://github.com/dada303312/research-daily-content-pipeline
>
> 一个内容工作流真正难的地方，不是“让模型写一篇文章”，而是让它在每天重复执行时，仍然知道选什么论文、什么情况下不能写、格式如何保持一致，以及失败后把问题交给谁。

我们把这个流程沉淀成了一个 Codex Skill：`research-daily-content-pipeline`。

它不是某个论文总结模板，而是一套可配置的日更操作系统。默认情况下，它每天运行三个研究领域：

| 时间 | 领域 |
|---|---|
| 08:30 | 钝化土壤微生物 |
| 09:00 | Na 土壤生态 |
| 09:30 | 固体废物和生活垃圾碳排放 |

每个领域每天做三件事：尽可能多地发现新的 Q1 / 一区 / 顶刊论文；选择一篇有完整全文的论文写成中文解读；按照统一的品牌排版生成公众号草稿并提交发布。

这篇文章拆解这个 Skill 的设计：为什么这样分层、每天怎么跑、哪些地方必须人工介入，以及怎样把它复用到别的账号和主题。

## 一、为什么要把日更做成 Skill

一开始，日更工作看起来像是“找一篇论文，然后写一篇稿”。

真正跑起来后，问题会立刻变多：

- 今天应该找哪些期刊？
- 最近 12 个月的新论文，和一篇高引用的旧论文，谁优先？
- Zotero 里已经有 PDF 吗？
- 找不到全文时，能不能只看摘要？
- 图表从哪里来？
- 公众号排版用什么主题？
- 签名条、封面、三连区是否和昨天一致？
- 微信要求扫码验证时，任务应该停在哪里？
- 发布完成后，appmsg ID、公开链接、Zotero key 记录到哪里？

如果每天都靠临时判断，质量就会漂移。更严重的是，模型可能在“没有全文”的情况下用摘要硬写，或者在排版上每篇改一点，最后看起来不像同一个账号。

Skill 的价值，是把这些判断变成稳定的默认行为。

## 二、Skill 的核心不是 Prompt，而是分层

这个 Skill 没有把所有规则堆进一个巨大的 prompt，而是拆成了四层：

```text
SKILL.md
  负责触发条件、硬门禁和运行顺序

references/fangcun-domains.md
  负责领域边界、期刊白名单、排期和输出路径

references/workflow.md
  负责从检索到发布的完整流程

references/quality-gates.md
  负责候选、全文、证据、写作、排版和发布检查
```

同时还有一个固定的品牌资产：

```text
assets/signature-bar.html
```

签名条不参与日常讨论。它就是一个组件，所有文章原样插入，不逐篇改写文案、颜色、字号、间距和圆角。

这种分层带来两个好处。

第一，修改领域配置时不需要动核心流程。例如从“固废碳排放”扩展到“建筑固废碳足迹”，只需要改领域文件。

第二，修改发布规则时不需要重写所有领域。例如把“默认群发通知关闭”改成“仅特定栏目开启”，只需要改质量门禁和发布规则。

## 三、每日运行：从候选池到一篇主稿

每个领域的运行分为八个阶段。

### 1. 发现候选

目标不是只找一篇，而是每期新增或更新 10–15 条候选。

候选池必须满足：

- JCR Q1、中科院一区，或领域公认顶刊；
- 主题落在当前领域边界内；
- DOI、标题、作者、年份、期刊和摘要可核验；
- 没有在历史成稿或已发布文章中出现过。

如果最终不足 10 条，系统必须记录检索式和不足原因，而不是随便找几篇补数量。

### 2. 按时间优先级排序

新的优先：

1. 最近 12 个月，包括 online first、advance access、in press；
2. 最近 3 年；
3. 3–5 年但高相关、高影响；
4. 更早文献只作为背景或经典理论来源。

这个排序不是为了追求“新”本身，而是因为公众号读者更关心最新进展。经典文献仍然重要，但它通常不是日更主稿的首选。

### 3. 去重和入库

每篇候选都要按 DOI、题名、Zotero item key、历史目录和发布记录去重。

Zotero 中至少记录：

```text
题名
作者
年份
期刊
卷期页码
DOI
摘要
领域标签
月份标签
状态
```

状态写成可检索的字段：

```text
queued
needs_pdf
drafted
reviewed
published
skipped
```

这样“今天为什么没写”和“明天优先写什么”都能从数据里看出来。

### 4. 全文门禁

这是整个工作流最重要的规则之一：

**没有全文，不写正式文章。**

优先使用 Zotero 里已经附带的 PDF。没有 PDF 时，再检索出版社 OA、机构订阅或作者合法公开版本。

如果仍然拿不到全文：

- 把候选标记为 `needs_pdf`；
- 记录题名、期刊、年份、DOI 和失败原因；
- 在日报里提醒账号运营者自行收集；
- 如果当天还有其他全文可用的候选，就换一篇；
- 如果没有，就暂停当天主稿，等待全文。

不能让模型用摘要“补全”一篇正式解读。摘要可以用于判断是否值得入库，但不能替代全文证据。

### 5. 提取证据和图表

确认全文后，先做证据提取，而不是立刻写开头。

需要整理：

- 研究问题；
- 系统边界和功能单位；
- 数据和时间范围；
- 方法；
- 主要结果；
- 反事实或情景假设；
- 研究限制。

图表从 PDF 原始图像对象中提取，不重绘、不改数据。对于碳相关论文，还要严格区分 CO2、CH4、N2O、CO2e、GWP、直接排放、下游排放和替代减排。

### 6. 中文撰稿

正文结构固定为：

```text
文章来源
研究简介
主要图文
关键数据
研究结论与边界
论文引用
```

主标题固定为：

```text
刊名｜中文核心发现
```

写作要求不是“看起来学术”，而是保留信息密度：

- 数值、单位、尺度不能丢；
- 机制和适用条件要说清楚；
- 模型估计、情景结果和实测数据要分开；
- 相关关系不能写成确定因果；
- 不写“值得注意的是”“未来可期”之类的套话。

### 7. 排版与视觉一致性

通过编辑门槛后，才进入排版。

统一使用 gzh-design 的“橄榄手记”主题，并使用：

- 头图卡；
- 编号分节；
- 原文图片卡；
- 浅底数据表；
- 重点观点卡；
- 暗色收束；
- 固定签名条；
- 三连区。

签名条来自固定资产：

```text
assets/signature-bar.html
```

排版完成后，还需要检查：

- HTML 校验是否 0 ERROR；
- 图片是否全部加载；
- 标题是否换行合理；
- 文献信息卡文字是否出边框；
- 封面 2.35:1 和 1:1 是否都能正常裁剪；
- 手机预览是否可读。

### 8. 发布与记录

最后才进入公众号发布。

默认不开启群发通知，选择“内容展示在公众号主页并允许平台推荐”的路径。只有用户明确要求时才开启群发通知。

如果微信要求管理员或运营者扫码验证，任务立即停在二维码页，保留浏览器标签，通知用户扫码。不能绕过平台安全验证。

发布完成后，记录：

- 草稿 ID；
- appmsg ID；
- 公开链接；
- 发布状态；
- 预览路径；
- Zotero item key 和 attachment key；
- 当日 `needs_pdf` 列表。

到这里，一次运行才算真正完成。

## 四、三个硬门禁

这个 Skill 的稳定性主要来自三个门禁。

### 门禁一：期刊层级

只收 JCR Q1、中科院一区或领域公认顶刊。低于这个层级的论文可以做背景，但不能进入主稿池。

### 门禁二：时间优先级

最近 12 个月优先，其次近 3 年，再其次 3–5 年高相关文献。旧文献不是不能用，而是需要明确理由。

### 门禁三：全文可用性

没有全文就不写正式稿。找不到全文时，不是静默降级，而是把问题交回给用户：

```text
needs_pdf
题名：...
期刊：...
年份：...
DOI：...
原因：Zotero 无附件，出版社和机构访问均未取得完整全文
```

这条规则看起来会降低每天的产出速度，但它保护的是内容质量。

## 五、哪些地方必须人工介入

Skill 的目标不是“全自动无人值守”，而是把重复劳动自动化，把高风险动作交给人工。

需要人工介入的场景包括：

1. 全文无法获取时，由用户提供 PDF 或原文；
2. 微信要求管理员或运营者扫码验证时，由用户扫码；
3. 平台拒绝发布或审核失败时，由用户决定是否修改或重试；
4. 用户要求改变群发通知、作者署名、原创声明等发布设置时，由用户明确授权；
5. 期刊层级、时间范围、领域边界发生变化时，由用户更新配置。

明确这些边界，反而让自动化更容易长期运行。

## 六、如何复用到其他领域

这个 Skill 的默认配置是三个领域，但核心流程与领域无关。

如果要新增一个领域，只需要增加一份配置：

```yaml
- id: soil-microplastics
  schedule: "10:00"
  output_dir: output/soil-microplastics
  scope:
    - microplastics in soil
    - plastisphere
    - soil fauna exposure
  journals:
    - Nature
    - Science
    - Environmental Science & Technology
    - Journal of Hazardous Materials
  candidate_target: 10-15
```

然后复用同一套流程：

```text
发现候选 → 去重入库 → 全文门禁 → 证据提取 → 中文撰稿 → 编辑审稿 → 统一排版 → 发布记录
```

领域变了，判断标准可以变，但输出契约不变。

## 七、总结

这套 Skill 解决的不是“怎么让模型写文章”，而是四个更具体的问题：

1. **每天写什么**：只从 Q1 / 一区 / 顶刊候选池中选，最近 12 个月优先。
2. **什么时候不能写**：没有全文时不写，标记 `needs_pdf`，把问题交回用户。
3. **怎么保证证据不丢**：固定结构、证据清单、数据口径和边界检查。
4. **怎么保证每次看起来都像同一个账号**：主题、信息卡、封面、签名条和发布记录全部组件化。

当这些规则被写进 Skill，日更就从“每天重新组织一次工作”变成了“每天运行一次确定的流程”。

模型负责检索、阅读、提取、写作和操作界面；人负责授权、补充全文、处理验证和决定边界。

这可能是目前最适合内容工作流的人机分工。
