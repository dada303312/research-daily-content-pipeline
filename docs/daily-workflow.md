# 研究日更统一工作流

这是一套把“论文发现 → 全文核验 → 中文撰稿 → 统一排版 → 公众号发布 → 结果记录”串起来的日更流程，适合研究型公众号、实验室内容组和知识运营团队。

## 一、三个领域与排期

| 时间（北京时间） | 领域 | 目标 |
|---|---|---|
| 08:30 | 钝化土壤微生物 | 每天一篇高质量文献解读 |
| 09:00 | Na 土壤生态 | 每天一篇高质量文献解读 |
| 09:30 | 固体废物和生活垃圾碳排放 | 每天一篇高质量文献解读 |

每个领域的目标不是只找一篇，而是每期尽量新增或更新 10–15 条候选，再从有完整全文的候选中选择一篇主稿。

## 二、候选搜集

- 只收 JCR Q1、中科院一区或领域公认顶刊。
- 最近 12 个月优先，其次是最近 3 年，再其次是 3–5 年高相关文献。
- 按 DOI、题名、Zotero item key、历史成稿和发布记录去重。
- Zotero 记录题名、作者、年份、期刊、卷期页码、DOI、摘要、标签和状态。

候选状态使用：

```text
queued
needs_pdf
drafted
reviewed
published
skipped
```

## 三、全文门禁

主稿必须来自可核验的全文。

优先使用 Zotero PDF；没有 PDF 时，检索出版社 OA、机构订阅或作者合法公开版本。如果仍然无法获取：

1. 标记为 `needs_pdf`；
2. 记录题名、期刊、年份、DOI 和原因；
3. 在日报中提醒运营者自行收集；
4. 不写摘要替代全文；
5. 有其他全文候选就换一篇，没有就暂停当天主稿。

## 四、撰稿与审稿

主标题统一为：

```text
刊名｜中文核心发现
```

正文顺序统一为：

```text
文章来源
研究简介
主要图文
关键数据
研究结论与边界
论文引用
```

保留数值、单位、尺度、机制、情景和限制条件；不把相关关系写成确定因果；不写套话。

## 五、排版与品牌一致性

统一使用 gzh-design“橄榄手记”主题，包含：

- 头图卡；
- 编号分节；
- 原文图片卡；
- 浅底数据表；
- 重点观点卡；
- 暗色收束；
- 固定签名条；
- 三连区。

签名条统一读取 `assets/signature-bar.html`，不得逐篇改写文案、颜色、字号、间距和圆角。

## 六、发布与记录

默认不开启群发通知，选择“内容展示在公众号主页并允许平台推荐”的路径。遇到管理员扫码验证时暂停，保留页面并通知运营者。

发布后记录：

- 草稿 ID；
- appmsg ID；
- 公开链接；
- 发布状态；
- 预览路径；
- Zotero item key 和 attachment key；
- 当日 `needs_pdf` 列表。

## 七、为什么这样做

这套流程的核心不是让模型“多写几篇”，而是保证每天重复执行时，仍然知道：

1. 写什么：从 Q1 / 一区 / 顶刊候选池中选，最近 12 个月优先。
2. 什么时候不能写：没有全文就不进入正式写作。
3. 如何保证不丢证据：固定结构、证据清单、数据口径和边界检查。
4. 如何保持品牌统一：主题、信息卡、封面、签名条全部组件化。

模型负责检索、阅读、提取、写作和界面操作；人负责授权、补充全文、处理验证和决定边界。
